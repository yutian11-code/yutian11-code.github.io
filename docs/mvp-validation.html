MVP & Growth Validation

用最轻的钩子验证重赌注：妆签传播验证 MVP

产品 MMU类型 MVP 设计2026.06

不实现完整产品，只用一个最轻的单点钩子快速上线，验证传播力与「重投入需求」两个假设；把埋点当作本期的产品本体，明确 YAGNI 不做什么。

MMU 传播验证 MVP 设计文档 —— 「美妆人设卡」微信小程序

  • 工作代号：妆签（可改名）
  • 日期：2026-06-20
  • 类型：传播验证型 MVP（小程序）
  • 状态：设计已与需求方对齐，待评审

0. 背景与目标

MMU 完整产品（见《产品功能表.xlsx》）是一个"美妆资产数字化 + AI 化妆师 + 社区 + 电商"的超级 App，三版路线图依赖三座"建库"大山（产品库 / 成分库 / 妆容模板库），上线前置成本极高，无法快速做市场验证。

本 MVP 的目的不是实现 MMU，而是用一个最轻的单点钩子，快速上线并验证两件事：

  1. 传播力：美妆 AI 玩法能否自然拉来流量、被用户主动分享。
  2. 重赌注的需求信号：用户对"AI 真换脸试妆"这个未来重投入到底有没有需求。

留存不是本期目标，优先级明确后置。

验证的核心假设

  • H1：一张"足够准 + 足够好看"的美妆人设卡，用户愿意主动截图分享。
  • H2："想看化在自己脸上的样子"对足够多用户有吸引力（用 CTA 点击/留资率度量），值得后续投入做真换脸。

1. 产品一句话

上传一张自拍 → AI 给你一张「美妆人设卡」（风格判定 + 五官解析 + 专属妆容方案）→ 截图去晒 / 转发好友 → 朋友扫小程序码也来测。

定位：美妆风格推荐工具（注意：对外与提审一律用"推荐工具"定位，不得使用"测命/预测/算"等测算类表述，规避微信审核风险）。

2. 范围

本期要做

  • 微信小程序（已认证主体）。
  • B：个性化「美妆人设卡」（风格人设 + 五官/脸型解析，不打分）。
  • A2：妆效预览（预生成静态图库展示，运行时不生成）。
  • A1：留资钩子（一键手机号授权 / 关注公众号）+ 需求埋点。
  • 分享：转发卡片 + 海报（小程序码）。
  • 全链路数据埋点（本期的"产品本体"）。

本期明确不做（YAGNI）

账号体系（仅用 openid）、产品库、成分库、真换脸（A1 首版只留资）、妆容模板库与匹配算法、社区、积分、电商、留存/复访机制、日历、化妆台、成分分析。

3. 核心链路（用户视角）

落地页（首屏看到样例卡，被勾住 + 隐私说明）
  → 上传自拍（拍照 / 相册）
  → AI 分析（品牌化 loading + 趣味文案）
  → 出「人设卡」 ★主角★
       ├ 风格人设标签（如「清冷氛围挂」）
       ├ 五官 / 脸型解析（脸型 · 眼型 · 适合的妆容重点；不打分）
       ├ 专属色调推荐
       ├ 一句锐评（夸赞向）
       ├ 妆效示范图（A2，按肤色档匹配的预生成图）
       ├ 推荐产品品类 + 3~5 步文字步骤
       ├ 稀缺感标注（「只有 X% 的人是清冷氛围挂」，X 由后台实时统计）
       ├ [CTA] 「想看化在你自己脸上的样子？」→ A1 内测留资 + 埋点
       └ [分享] 保存卡片图 / 生成带小程序码海报 / 转发好友
  → 他人扫小程序码 / 收到转发卡片 → 回到落地页（闭环）

4. 模块设计

4.1 B —— 人设卡（重中之重，承载全部"个性化"和"传播"）

  • 风格库：固定 6~8 个"挂"，例如：清冷氛围 / 甜辣 / 纯欲 / 复古港风 / 元气少女 / 欧美高级 / 温柔氧气 / 酷飒中性。
  • 每个"挂"预置静态内容：定义文案、推荐色调、妆容重点、3~5 步文字步骤、妆效示范图（× 肤色档：白 / 中 / 深）。
  • 个性化来源：一次多模态视觉模型调用。
  • 输入：用户自拍。
  • 输出：结构化 JSON —— 脸型、眼型、肤色档(白/中/深)、命中风格(枚举之一)、专属锐评(夸赞向短句)。
  • 解析与锐评为真·按人生成；风格落入固定桶；步骤 / 示范图取自该桶模板。
  • 稀缺感钩子（促分享，近零成本）：卡片展示"只有 X% 的人是 XX 挂"，X 由后台对历史命中分布实时计算。
  • 设计质量要求：卡片是用户截图去晒的主角，视觉必须精致、可直接当海报。卡片图通过小程序 Canvas 渲染为可保存图片。

4.2 A2 —— 妆效预览（灵感示范图）

  • 纯展示预生成静态图库。
  • 图库矩阵：风格 × 肤色档。上线前用文生图模型当美术工具批量产出、人工精修挑定稿，存对象存储 + CDN。
  • 运行时不调用任何生成模型（速度、成本、质量、合规均最优）。
  • 按 B 测出的肤色档匹配对应示范图，产生"挑给我的"感。
  • 文案定位明确为"风格妆容示范图"，不承诺是用户本人。

4.3 A1 —— 留资钩子（验证 H2 的核心数据）

  • 卡底 CTA：「想看化在你自己脸上的样子？」点击 → 弹"专属试妆内测中"。
  • 留资方式（小程序红利，禁止引导加个人微信 / 跳外链）：
  • 微信一键手机号授权（零输入，转化率高；依赖企业/个体主体）。
  • 或 关注关联公众号 做后续触达。
  • 关键埋点：CTA 点击率 + 一键授权率 = "AI 真换脸"重投入是否值得做的直接证据。

4.4 分享 / 裂变

  • 转发给好友 / 群：小程序原生 onShareAppMessage，自定义卡片标题与封面图。
  • 朋友圈：微信限制无法直发小程序 → 靠"保存人设卡图 / 海报再发"（故卡片图必须漂亮）。
  • 海报：Canvas 合成「人设卡 + 小程序码 + 一句引导文案」，可保存。
  • 一键文案示例："测测你是什么妆容挂 👉"。

5. 技术架构（极简）

  • 前端：微信小程序。推荐原生（WXML/WXSS/JS）以最小化开销；若团队需多端可选 Taro（React 系）。卡片/海报用小程序 Canvas API 渲染。
  • 后端：单个轻量 API 服务。
  • 职责：接收图片 → 调多模态视觉模型 → 校验/映射到风格枚举 → 返回结果 JSON。
  • 统计接口：返回当前各风格命中分布（供稀缺感百分比）。
  • AI：多模态视觉模型，结构化输出（脸型/眼型/肤色/风格/锐评一次返回）。需用 system 约束输出 JSON Schema 与"正向、非诊断"措辞。
  • 静态资源：妆效图库 + 卡片底图素材，放对象存储 + CDN。
  • 数据存储：
  • 事件表（埋点）—— 本期产品本体。
  • 留资表（openid / 手机号 / 来源风格 / 时间）。
  • 风格命中计数（供稀缺感统计）。

数据流

小程序上传图片 → 后端 API → 视觉模型(结构化JSON)
  → 映射风格桶 + 取静态模板 → 返回结果JSON
  → 小程序渲染人设卡(Canvas) → 用户分享/留资 → 埋点入库

6. 成功指标（本期真正目的）

验证什么 指标
能不能传（H1） 分享率(分享数/出卡数)、海报扫码/转发回流 UV、K 因子
漏斗顺不顺 落地→上传→出卡 完成率，各步流失率
重赌注有无需求（H2） A1 CTA 点击率、一键留资转化率
哪些"挂"最受欢迎 各风格命中分布、各风格分享率

验证窗口与目标阈值（如"分享率 ≥ X%、CTA 点击率 ≥ Y% 则判定 H2 成立"）由需求方在评审时补充确认。

7. 错误处理 / 边界

  • 上传非人脸 / 多人脸 / 过于模糊 → 友好提示重传，不阻断。
  • 视觉模型调用失败 / 超时 → 兜底给一个保底风格 + 提供重试。
  • 模型输出不符合枚举 / Schema → 后端做枚举纠偏，兜底到最接近风格。
  • 用户拒绝授权手机号 → 不阻断，仍可分享，记录"拒绝授权"事件。

8. 风险与合规

  • 微信审核（高优先级风险）：测试/测算类小程序易被判违规。全程定位为"美妆风格推荐工具"，文案避开"测命/预测/算"等表述；强调"妆容推荐/风格参考"。
  • 容貌焦虑合规：不打分；锐评一律正向；禁用医疗/诊断措辞。
  • 隐私：自拍阅后即焚 / 不存原图；落地页明确隐私说明（美妆人群对此敏感，影响信任与转化）。
  • 手机号合规：留资需明示用途与同意；遵守个人信息相关规范。

9. 前置条件（阻塞上线，可与开发并行）

  • 微信小程序已认证主体：需求方当前没有。建议立即注册企业 / 个体工商户主体并认证（约 ¥300/年，材料齐全约 1~3 个工作日）。个人主体不可用"获取手机号"等能力，会废掉 A1 留资红利，不采用。
  • 多模态视觉模型 API 的账号 / 额度。
  • 对象存储 + CDN。
  • 上线前完成妆效图库（风格 × 肤色档）的批量生成与精修定稿。

10. 关键取舍（一句话）

B 卡片承载全部"个性化"与"传播"，A2 当灵感示范图，A1 只收需求信号。 把所有开发力气压在"卡片够准、够好看、够想晒"和"埋点拿到验证数据"上。
