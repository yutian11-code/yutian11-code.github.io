MMU 产品需求文档（PRD）

1. 执行摘要

我们为买了一堆化妆品却不会用的化妆新手做一款 App（MMU），解决他们「买了不会用、用时找不到、教程和手里的产品不匹配」的核心痛点。做法是：识别用户已经拥有的化妆品建立数字化妆台，基于这些产品用 AI 生成适配妆容，再用分步教学手把手教用户化出来。预期结果是把「不会用」转化为「用得上」，用「结构化教学交付」而非「卖货种草」建立差异化，跑通「SaaS 订阅 + 美妆电商 CPS」的商业模式。

一句话：我们为化妆新手做「基于已有产品的 AI 分步化妆教学」，解决「买了不会用」，从而把闲置化妆品盘活成可持续的订阅与导购价值。

2. 问题陈述

谁有这个问题

化妆新手与进阶用户——尤其是已经囤了不少化妆品、但化妆技术跟不上的女性用户。

问题是什么

用户最大的痛点不是「没有好产品」，而是「买了不会用、用时找不到、跟着教程也化不出同样效果」。市面产品几乎都在解决「卖货」，很少有人解决「教你用已经拥有的化妆品化好一个妆」。

为什么痛

  • 白领：早上时间紧张找不到产品、经常重复购买、网上教程用的产品和自己手里的对不上。
  • 下沉市场用户：化妆技术差，不知道怎么用现有产品，容易被种草冲动购买。
  • 学生：预算有限，买了不会用，也不知道不同场合该化什么妆。

证据

  • 竞品调研（4 大渠道、跨赛道 27 款）显示：市场结构性地「重销售、轻教学」，没有一款产品「基于你手上的化妆品、分步骤带你化妆」。
  • 内测问卷验证：用户对「分步教学」好评率 92.19%，是最强的痛点命中信号。

3. 目标用户与画像

主画像 · 一二线城市白领（内测占比 52.0%）

  • 人群：25–45 岁，月收入 8k–20k，分布北上广深及新一线。
  • 现状行为：人均拥有 23 件美妆产品，37% 拥有超 5 件未开封产品。
  • 痛点：早上找不到产品、重复购买、教程与手里产品不匹配。
  • 对应方案：数字化妆台（内测 85.16% 认可分类清晰）+ 基于现有产品的 AI 妆容匹配，盘活闲置、杜绝重复购买。

次画像

  • 下沉市场女性（34.7%）：18–30 岁，月收入 3k–8k，人均 12 件产品，对「性价比 / 实用性」极敏感 → 分步教学替代盲目种草。
  • 学生（10.2%）：18–24 岁，月生活费 1.5k–3k，人均 8 件，时间充裕、乐于尝鲜，是口碑裂变的核心引擎 → 场景化妆容（通勤 / 约会 / 面试）在有限预算内做效果最大化。

用户要完成的任务（Jobs-to-Be-Done）

  • 当我面对一堆化妆品不知道怎么组合时，我想要一个基于我已有产品的妆容方案，好让我不用再额外买东西就能化好一个妆。
  • 当我跟着网上教程化不出效果时，我想要一步步只告诉我这一步用哪支、怎么涂，好让我真的能复现。

4. 战略背景

业务目标

用「结构化教学交付」切入美妆赛道，先验证核心价值（教会用户化好一个妆），再在价值验证之上做商业化，跑通「教学订阅做留存 + 电商分佣做变现」的双轮模式。

市场机会

美妆是高频、高客单的大众需求；「基于已有产品的教学」是竞品普遍忽略的结构性空白。

竞品格局

  • 电商导购型：解决「买什么」，不解决「怎么用」。
  • 泛美妆内容型：内容泛化，不针对用户手里的具体产品。
  • 结论：无人占据「用你已有的产品、分步教你化好一个妆」这个位置——即 MMU 的差异化入口。

为什么是现在

多模态视觉模型已能做到「识别产品 + 基于产品生成妆容 + 分步指导」，此前纯人工内容无法规模化的教学交付，现在有了技术可行性。

5. 方案概述

方案描述

把 AI 能力落到「识别已有化妆品 → 生成适配妆容 → 分步骤实时指导 → 完成度反馈」这条主链路上。MVP 阶段主动砍掉社区、商城等非核心模块，只保留「分步教学」主链路，确保最快验证核心假设。

flowchart LR
    A["识别已有化妆品<br/>扫码/拍照/文字录入"] --> B["数字化妆台<br/>分类·成分·保质期·余量"]
    B --> C["输入场景与偏好<br/>通勤/约会 · 难度 · 限制"]
    C --> D["AI 生成适配妆容<br/>基于现有产品·三路召回重排"]
    D --> E["分步骤实时指导<br/>每步用哪支·怎么涂"]
    E --> F["完成度反馈 / 妆后总结<br/>记录·复盘·下次建议"]
    F -.回流.-> B

核心功能（按模块，摘自产品功能规格）

模块 关键功能 交付的价值
一、美妆资产数字化 扫码/拍照/文字录入、产品搜索匹配、开封/未开封保质期、余量记录、成分分析、化妆台分类管理 盘活闲置、杜绝重复购买、看清手里有什么
二、用户画像 肤质/肤色/敏感/熟练度资料、历史妆容与使用记录 让推荐锚定「这个人 + 这些产品」
三、AI 妆容推荐 基于「用户画像—产品库—场景风格」三路召回与重排，只推荐用现有产品能完成的妆容 不用额外买东西就能化好一个妆
四、分步教学 妆容拆成分步骤、每步指定产品与手法、实时指导 真的能复现（好评 92.19%，核心壁垒）
五、妆后总结 记录日期/产品/步骤/耗时、余量快速更新、下次建议 形成「学 → 做 → 改」闭环、沉淀复购数据

关键用户流

落地 → 录入/识别已有产品 → 建立化妆台 → 选场景与偏好 → AI 出妆容方案 → 进入分步教学（可选自拍试妆预览）→ 完成后妆后总结 → 回流到化妆台。

6. 成功指标

北极星指标

核心场景启动率（看到心仪妆容后真正开始跟妆的比例）。内测实测 71.89%——验证「一旦看到心仪妆容，立刻动手」的意愿极强，是 PMF 的核心信号。

次级指标

指标 内测实测 说明
推荐意愿（NPS 代理） 89.06% 口碑与裂变潜力
分步教学好评率 92.19% 核心体验与留存抓手
化妆台分类清晰认可 85.16% 资产数字化的可用性
推荐入口点击率 71.38% 前端吸引力

护栏指标

完整跟妆完成率：内测仅 24.23%（漏斗：曝光 1520 → 点击 1085 → 启动 780 → 完成 189）。前端极具吸引力、后端流失严重，主因是当前 MVP 的 AI 渲染时长与单次视频过长——不是需求伪命题，而是工程体验问题，需以「断点续妆 / 缩短单步」优化。

7. 用户故事与需求

Epic 假设

如果我们让用户基于已有产品拿到 AI 妆容并被分步骤带着化，那么新手就能真正化好一个妆，从而愿意推荐并为「教学订阅 + 精准导购」付费。

用户故事（节选，MoSCoW）

  • Must：作为白领用户，我想扫码/拍照录入我的化妆品，以便建立我的数字化妆台。
  • Must：作为新手，我想拿到只用我现有产品就能完成的妆容方案，以便不额外花钱就能化妆。
  • Must：作为新手，我想被一步步告诉每步用哪支、怎么涂，以便真的能复现妆容。
  • Should：作为用户，我想在跟妆中途退出后能断点续妆，以便不因单次过长而放弃。
  • Should：作为用户，我想看到产品成分与保质期，以便安全、及时地用掉手里的产品。
  • Could：作为用户，我想做自拍试妆预览，以便先看到大致效果再开始。

约束与边界情况

  • 录入是低频动作，「录入劝退 × 低频 = 留存陷阱」是明确风险（竞品侧已被独立验证），第一版录入必须做到极简、可跳过、可后补。
  • 自拍相关能力遵守合规底线：不打分、非医疗/诊断、阅后即焚不存原图。

8. 范围外

本期不做

  • 社区/UGC、内置商城、2.5D 虚拟化妆台的重交互形态、真人换脸级试妆——第一版一律不做，避免拉长上线、稀释核心验证。

未来考虑

  • 空瓶复购提醒、保质期营销（依赖化妆台沉淀的数据）。
  • 电商 CPS 深度选品、会员精准色彩诊断等付费深度功能。
  • 针对冷启动/传播的更轻钩子（后续「自拍看穿」pivot 即由此而来）。

9. 依赖与风险

依赖

  • 多模态视觉模型（产品识别 + 基于产品的妆容生成）。
  • 产品库/成分库/妆容模板库的建设（重资产，直接影响上线成本）。

风险与缓解

风险 影响 缓解
录入劝退导致留存差 用户建不起化妆台，后续推荐无从谈起 录入极简化、可跳过；先用轻资产钩子拉人，录入后置
AI 渲染时长长 → 完成率低（实测 24%） 核心体验断在最后一公里 断点续妆、缩短单步视频、异步生成
建库前置成本高，无法快速验证 上线慢、烧钱 MVP 先做最小产品库 + 手工兜底；用轻 MVP 验证需求再投入建库
冷启动/传播弱 有 PMF 信号但拉不到量 后续以更轻的可分享钩子做冷启动（pivot 依据）
