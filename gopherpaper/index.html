多智能体科研文献解析平台 —— 让文献从「读一篇」变成「管理一个知识体系」

针对科研读文献读得慢、问不深、记不住，以及现有 AI 工具回答会编造出处的信任问题。产品把「每条回答附页码出处、可点击溯源」定为第一原则，并用自建评测集验证这条原则真的成立。

02 · 三个产品决策Why it looks like this
范围

MVP 只做两件事

面对「解析 / 问答 / 知识库 / 研报 / 多模态检索」的庞大需求，MVP 阶段只保留论文解析 + 证据问答，用「论文精读 / 学术检索 / 知识管理」三个角色化智能体分工承接，其余功能后置。

信任

出处是第一原则

AI 阅读工具最大的信任问题是编造出处。于是每条回答必须附页码、可点击跳回原文，用户不用盲信，而是能一键核验。这条原则决定了分块方式、检索方式和界面。

成本

质量和 token 一起管

用意图小模型给高频轻问题分流，用会话摘要治理多轮上下文，多模态检索配两阶段 rerank 精排。回答质量和成本不是二选一，是一起设计。

05 · 自建评测：原则有没有兑现Evaluation

「回答可信」不能靠感觉。我用 18 篇公开论文构造了 50 题评测集（事实 26 / 推理 12 / 表格 7 / 不可答 5），每题标注金标准答案与页码，脚本自动跑问答、LLM 评分并人工复核。

指标结果怎么算的
答案正确率87.0%50 题事实 92.3% · 推理 83.3% · 表格 78.6% · 不可答 80%
溯源召回率95.6%43 / 45可答题中，引用页里命中任一正确页码的比例
溯源精度31.3%61 / 195引用页里真正正确的比例 —— 明显偏低，是当前主要弱点
拒答正确率80%4 / 5论文里没有的信息，是否诚实说「没有」而不是编
我怎么看这组数字

召回高、精度低，说明系统「宁多勿漏」：答案基本能找对页，但一次给出的引用页太多，用户核验成本高。这是我下一轮要改的点：按相关度截断引用、只保留支撑最终答案的片段。评测集本身的弱点我也认：单人标注、LLM 评分未全量人工复核、论文领域集中在深度学习经典论文。

06 · 团队与我的部分My part

GopherPaper 是团队项目，后端主体由团队同学完成。我作为产品负责人，具体做了这些：

  • 需求范围与 MVP 界定：把庞大需求收敛为「解析 + 证据问答」两件事，定义三个智能体的分工边界。
  • 反幻觉第一原则：把「页码出处 + 可点击溯源」写进产品原则，并推动分块、检索、界面按这条原则设计。
  • 评测体系：自建 50 题评测集、评分脚本与报告，让「可信」变成能量化、能迭代的指标。
  • 后台管理台与数据看板：动手开发。把后台重构为分页模块，删掉运维式看板，改成产品视角的「分析概览」。
  • 入库排障：批量上传触发限流，出现「状态 ready 但零分块」的假就绪，我从 Milvus 侧定位并修复，这也是为什么评测最终只用了 18 篇。
口径说明：系统在本地环境部署运行，未公网上线，所以这里放的是录屏与截图而不是在线体验入口。视频为真实操作录屏，评测数据来自自建评测集而非线上用户数据，所有数字可在面试时展示脚本与原始记录复现。
